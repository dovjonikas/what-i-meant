# Engines, frameworks and narrative tools for a phones-first browser story-game collection (late October 2026)

Scope: a hub page with several stories, each its own small game with its own look (pixel, realistic or 3D, painterly) and its own way to play (tap through, walk around, scroll), released in episodes, hosted free on GitHub Pages from a public repo, coded mostly by Claude Code with the creator. Research date: 2026-10-29. Versions are the newest found; where a newer patch may exist it is said so. No em dashes or tildes are used in these notes ("about" replaces the tilde).

## 1. Engines and renderers: which fit pixel 2D, which fit a realistic 3D look, and can several engines live in one site?

### Takeaway
For a phones-first, agent-coded collection, the strongest fits are code-first JavaScript/TypeScript libraries that load per page: plain DOM/CSS for tap-through and scroll stories, Phaser 4 (MIT, 345 KB gzipped full build) or PixiJS 8 (MIT, about 200 KB) for pixel 2D, and Three.js r186 (WebGL2 now, WebGPU where available) for a 3D or realistic look. Godot 4.7 is the best "real engine" for the web but costs about 9 MB gzipped per story, is WebGL2-only on the web and still has documented iPhone Safari rough edges; Unity 6 is heavier still. Different stories can use different engines because each story can be its own HTML entry that loads only its own engine.

**Godot web export, current state**
- Single-threaded export has been possible since 4.3 and is "the preferred and now default way to export your games on the Web"; thread support needs cross-origin isolation headers ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)).
- "The single-threaded export works very well on macOS and iOS too", but "Safari has several issues with WebGL 2.0 support that other browsers don't have" ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)).
- Web is WebGL 2.0 only, Compatibility renderer; "Forward+/Mobile are not supported on the web platform" ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)).
- "Projects written in C# using Godot 4 currently cannot be exported to the web" ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)).
- Audio uses Web Audio since 4.3; in Sample mode AudioEffects and procedural audio are unsupported; Stream mode raises latency, "especially when thread support is disabled" ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)). A 4.6.1 to 4.6.3 user reports audio only worked after switching playback type to Stream ([Godot forum](https://forum.godotengine.org/t/no-audio-in-web-export/136174)); music sync drift on web in 4.6.3 ([Godot forum](https://forum.godotengine.org/t/audio-sync-not-working-on-web-exports/140145)).
- The wasm compresses to about a quarter with gzip; GitHub Pages serves on-the-fly gzip, itch.io does not ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)).
- Size regression: since 4.6.1 exports include a 4.8 MB ICU data file; unexplained increases also reported in 4.6.2, 4.7 and 4.8 dev builds ([issue #123606](https://github.com/godotengine/godot/issues/123606)). Custom export templates disabling 3D, WebRTC and CSG reportedly cut about 40% of the binary ([community guide](https://xjustice.github.io/articles/optimizing-godot-4-web-exports.html)).
- iPhone stability: Feb 2026 issue, Godot 4.5.1 web export crashes Safari on iPhone 12 / iOS 26.3 after 10 to 30 minutes of repeated `AudioStreamPlayer.play()` ([issue #116750](https://github.com/godotengine/godot/issues/116750)); 2 GB max wasm memory caused out-of-memory on iOS 16.2, 256 MB fixed it ([issue #70621](https://github.com/godotengine/godot/issues/70621)); WebGL context loss and crash on iOS in 4.3 ([forum](https://forum.godotengine.org/t/webgl-context-loss-and-app-crash-in-godot-4-3-exported-web-on-ios-browsers/81024)); forum rule of thumb keeps runtime memory under about 300 MB on iOS (anecdotal) ([forum](https://forum.godotengine.org/t/game-crashes-randomly-on-ios-devices-html-export/114043)). Cinevva's Sep 2026 comparison still says "Safari/iOS support is problematic" ([Cinevva](https://app.cinevva.com/guides/web-game-engines-comparison)).
- `user://` persistence on web uses IndexedDB and fails in incognito ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)).

**WebGPU on iPhone**
- WebGPU shipped in Safari 26.0 for macOS, iOS, iPadOS and visionOS ([WebKit blog](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)), released with iOS 26 in September 2025 and on by default; it requires iOS 26 or later ([AppDeveloperMagazine](https://appdevelopermagazine.com/webgpu-in-ios-26/), [web.dev](https://web.dev/blog/webgpu-supported-major-browsers)).

**Phaser 4 details**
- 4.0.0 "Caladan" (10 Apr 2026) is a ground-up rebuild of the WebGL renderer; public API largely kept from Phaser 3, so migration is lighter than expected; sprite layers push "on the order of a million sprites" in one draw call; GPU tilemaps, unified filters, lighting ([playfox](https://playfox.org/news/html5-engine-2026/), [Phaser 3 vs 4](https://phaser.io/news/2026/05/phaser-3-vs-phaser-4)).
- 4.2.0 added Mesh2D, stencil rendering and AlphaStrategy ([Phaser news](https://phaser.io/news/2026/06/phaser-v4-2-0-released)).
- Earlier claims that Phaser 4 defaults to WebGPU and is about 40% faster were retracted by playfox ([playfox](https://playfox.org/news/html5-engine-2026/)).
- Full TypeScript definitions ship in the package ([GitHub](https://github.com/phaserjs/phaser)).

**PixiJS 8 details**
- v8.16.0 (4 Feb 2026) added an experimental Canvas renderer as last-resort fallback ([playfox](https://playfox.org/news/html5-engine-2026/), [PixiJS 8.16](https://pixijs.com/blog/8.16.0)); v8.19.0 added opt-in `pixi.js/html-source` that renders live DOM elements into textures ([PixiJS June 2026](https://pixijs.com/blog/june-2026)).
- Passed 500,000 weekly npm downloads in June 2026 and ships 25 official skills for AI coding agents ([playfox](https://playfox.org/news/html5-engine-2026/)).

**General engine recommendations from 2026 comparisons**
- Phaser 4 for full 2D games, PixiJS 8 for pure rendering, Kaplay for prototypes and jams, Three.js or Babylon.js for 3D; "treat WebGPU as a later decision" ([playfox](https://playfox.org/news/html5-engine-2026/)).
- Babylon.js is called production-ready on WebGPU "since v5"; Three.js WebGPURenderer was "not production-recommended yet" as of Mar 2026 (that article's data used Three.js r162, so it is dated) ([PkgPulse](https://www.pkgpulse.com/guides/threejs-vs-react-three-fiber-vs-babylonjs-3d-webgl-2026)).

### Inferences
- **Pixel 2D**: Phaser 4 is the best fit for "walk around" pixel stories (scenes, input, cameras, tilemaps, arcade physics included); PixiJS 8 suits stories that are mostly layered art with light interaction; Excalibur is a TypeScript-native alternative with a pixel-art flag but has had no release in 10 months. Kaplay is still alpha on its new major, so avoid it for something meant to last.
- **Realistic or 3D look**: Three.js is the default pick (huge corpus of examples for an AI agent to draw from, tree-shakable, WebGL2 path works on every iPhone, WebGPU path for iOS 26+). Babylon.js is the runner-up (more batteries included, heavier). Babylon Lite and anything WebGPU-only would exclude iPhones not on iOS 26, so it is not suitable as the only path yet. Three.js WebGPURenderer is generally documented to fall back to a WebGL2 backend when WebGPU is missing (not re-verified in this pass).
- **Painterly or tap-through or scroll stories** need no game engine at all: DOM, CSS, SVG and a single canvas with GSAP-style animation are lighter, more accessible, and easiest for an agent to test (text is real DOM text that Playwright can read).
- **Godot** is the best single tool if the creator wants a visual editor and both 2D and 3D, but on the web it is WebGL2 Compatibility-only, about 9 MB gzipped plus assets per story, has open iPhone Safari crash and audio reports in 2026, and cannot use C#. As a per-story option inside the hub it works technically (one iframe or page per story) but costs load time on phones.
- **Unity 6 web** is the poorest fit: heavier, paid tiers above revenue thresholds, a binary-heavy editor workflow that an agent cannot drive well, and iOS memory caution.
- **Defold** is impressively small (under about 1.2 MB) but Lua-based with its own editor, which reduces the TypeScript and agent-tooling advantage.
- **Mixing engines in one site is fine**: each story as its own HTML entry means Phaser loads only on the Phaser story, Three.js only on the 3D story, and the hub stays tiny. The shared parts (saves, audio unlock, episode menu, narrative runtime) live in a small shared TypeScript package.

### Gaps
- No 2025 to 2026 benchmark measured Phaser 4, PixiJS 8 and Three.js frame rates on real iPhones; numbers above are bundle sizes, not FPS.
- Kaplay and LittleJS bundle sizes, and Kaplay's licence, were not found in this pass.
- Godot 4.7 release notes did not mention web changes; whether 4.7.x fixed the iOS audio crash (#116750) or the ICU size regression is unconfirmed.
- PixiJS may have releases after 8.19.0 (June 2026); not confirmed.
- Safari's per-tab memory ceiling on current iPhones is only known from anecdotes (about 300 MB Godot forum, below 500 MB Unity forum).

## 2. Narrative scripting: which lets the creator write his own text in plain files, with branching and state, and is easy to use from TypeScript?

### Takeaway
Ink with inkjs is the clear fit: plain `.ink` text files, branching, variables and state, an MIT-licensed JavaScript runtime with TypeScript types (inkjs 2.4.0, ink 1.2 compatible), a compiler usable from npm or the CLI, and saved state as JSON. Yarn Spinner still has no official JavaScript runtime in 2026; Twine, Ren'Py and ChoiceScript are complete authoring systems that own the whole page and do not mix well with custom engines; Dialogic 2 is Godot-only and still alpha.

### Cited Findings
- **inkjs**: latest v2.4.0 (17 Feb; year inferred as 2026 from the release order after v2.3.2 on 7 Apr 2025) ([GitHub releases](https://github.com/y-lohse/inkjs/releases), [npm](https://www.npmjs.com/package/inkjs)). v2.3.0 brought in the ink 1.2 updates ([GitHub releases](https://github.com/y-lohse/inkjs/releases)). Licence MIT; TypeScript imports via `import { Story, Compiler } from 'inkjs/types'`; the runtime is the default package, the compiler is in `inkjs/full`; CLI via `npx inkjs`; describes itself as "fully compatible with the original version" of inkle's ink ([GitHub](https://github.com/y-lohse/inkjs)). v2.4.0 added save and load to the CLI player; v2.3.1 added stats generation ([GitHub releases](https://github.com/y-lohse/inkjs/releases)).
- inkle's own inkjs page is outdated (old compatibility table, "No releases published"); the maintained repo is y-lohse/inkjs ([inkle/inkjs](https://github.com/inkle/inkjs), [y-lohse/inkjs](https://github.com/y-lohse/inkjs)). Ink itself: latest tag 1.2.1 on inkle's releases page ([inkle/ink releases](https://github.com/inkle/ink/releases)).
- **Yarn Spinner**: core compiler, runtime and integrations are free and open source; latest release named in Jan 2026 is Yarn Spinner 3.1 for Unity (Dec 2025); 2026 plans are a rebuilt VS Code extension, Unreal support, a Visual Novel Kit and the web playground try.yarnspinner.dev; no JavaScript or npm runtime is mentioned ([Yarn Spinner in 2026, 5 Jan 2026](https://yarnspinner.dev/blog/yarn-spinner-in-2026)). An older 3.0 post promised a JavaScript runtime as an npm package ([Patreon](https://www.patreon.com/posts/yarn-spinner-3-0-96578347)); the Jan 2026 update says a standalone Playground for web-based games is still in development ([Jan 2026 update](https://yarnspinner.dev/blog/monthly_jan_26/)). A GDScript port for Godot was in alpha in Feb 2026 ([Feb 2026 update](https://yarnspinner.dev/blog/monthly_feb_26/)). A community browser sandbox runs the C# compiler in WebAssembly but is a parser and visualiser, not a runtime ([yarn-playground](https://github.com/wickes1/yarn-playground)).
- **Twine**: 2.12.0 on 10 Apr 2026 (tag display in story map, Japanese, Electron 41) ([IFTF blog](https://blog.iftechfoundation.org/2026-04-12-twine-version-2120-released.html), [2.12 notes](https://twinery.org/reference/en/release-notes/2-12.html)); 2.12.1 on 7 Oct 2026 ([GitHub](https://github.com/klembot/twinejs/releases)). SugarCube latest v2.37.3 (2.37.0 dated 2024-07-17) ([GitHub](https://github.com/tmedwards/sugarcube-2/releases), [release notes](http://www.motoslave.net/sugarcube/2/releases.php)); Harlowe newest found 3.3.9, no Harlowe 4 ([Twine 2.9 notes](http://twinery.org/reference/en/release-notes/2-9.html)).

### Inferences
- Ink matches every requirement: the creator writes the words in plain `.ink` files in his own voice (no code around the sentences), the agent wires tags like `# bg: forest` or `# sfx: rain` to each story's renderer, and the same runtime drives a tap-through DOM story, a Phaser walk-around (dialogue on interaction) or a Three.js scene. Story state serialises to JSON (inkjs follows the C# runtime's state JSON API; not re-verified in this pass), which fits localStorage saves per episode.
- Compile `.ink` to JSON at build time (Vite plugin or `npx inkjs` script) and ship only the small runtime; keep `inkjs/full` out of the phone bundle. Ink stories can also be unit-tested in Node with no browser (walk every choice, assert no dead ends).
- Twine (SugarCube/Harlowe) is excellent for pure text but each story becomes a Twine-owned HTML page; good for a quick prototype, weak for custom pixel or 3D presentation. Ren'Py web ships a whole Python runtime in wasm per story, heavy for phones. ChoiceScript's licence and fixed look rule it out. Yarn Spinner is a non-starter on the web until its JS runtime ships.

### Gaps
- No measured size for the inkjs runtime bundle was found.
- Community JavaScript Yarn runtimes (for example bondage.js, yarn-bound) were not checked for 2026 maintenance.
- Chapbook's current version, and Twee 3 plus Tweego (plain-text Twine authoring) status, were not checked.
- Whether a GDScript ink runtime for Godot web is maintained in 2026 was not checked (godot-ink is generally C#-based, which cannot export to web per the Godot docs above; unverified for 2026).
- Ren'Py's licence was not re-verified in this pass.

## 3. Structure and build: Vite with TypeScript, multi-page app, saves, PWA and offline, phone asset limits, GitHub Pages limits and Actions deploys

### Takeaway
Vite 8 (stable since 12 Mar 2026, Rolldown bundler, docs at v8.3.4) supports a multi-page app natively: list each story's `index.html` as an input and set `base` to the repo subpath for GitHub Pages. GitHub Pages allows a 1 GB published site, about 100 GB per month soft bandwidth, a 10-minute deploy timeout and no commercial use; Actions-based deploys skip the 10 builds per hour limit. On iPhone, Safari can delete script-written storage after 7 days of Safari use without visiting the site unless the site is added to the Home Screen, so saves need an export or backup path, and audio needs a tap plus the silent-switch workaround.

### Cited Findings
- **Vite 8** went stable on 12 Mar 2026, replacing esbuild plus Rollup with the Rust bundler Rolldown ([listiak.dev](https://listiak.dev/blog/vite-8-one-bundler-to-rule-them-all), [InfoQ](https://www.infoq.com/news/2026/05/vite-v8-rust/), [Vite 8.1 announcement](https://vite.dev/blog/announcing-vite8-1)); InfoQ reports some builds falling from 46 s to 6 s ([InfoQ](https://www.infoq.com/news/2026/05/vite-v8-rust/)); Rolldown 1.0 reportedly on 7 May 2026 (single source) ([buildmvpfast](https://www.buildmvpfast.com/blog/rolldown-vite-8-rust-bundler-2026)). The build guide shows v8.3.4 ([Vite docs](https://vite.dev/guide/build)).
- **Multi-page app**: in dev, nested `/nested/` pages work like a static server; for build, list each `.html` as an entry (`input: { main: ..., nested: ... }`, prose refers to `rolldownOptions.input`); set `base` for subpath deploys and use `import.meta.env.BASE_URL` for runtime URLs; `"./"` gives a relative base ([Vite docs](https://vite.dev/guide/build)).
- **GitHub Pages limits**: repository recommended under 1 GB; published site under 1 GB; deployments time out after 10 minutes; soft bandwidth 100 GB per month; soft 10 builds per hour, not applied to custom GitHub Actions workflows; no separate per-file limit stated; 429 on rate limiting; not for online business, e-commerce or commercial SaaS ([GitHub docs](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)).
- GitHub Pages compresses with gzip on the fly ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)). Threaded Godot builds need COOP/COEP headers or the PWA service-worker workaround, otherwise "the project will not run"; the single-threaded default needs neither ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html), [summerengine guide](https://www.summerengine.com/blog/godot-web-export-guide)).
- **Saves on iPhone**: Safari deletes all script-writable storage (localStorage, IndexedDB) for a site after 7 days of Safari use without interaction with it; the count is days of use, not calendar days; Home Screen web apps get their own counter and their first-party domain is exempt from the 7-day cap; `navigator.storage.persist()` exists since Safari 15.2 but is granted by heuristics, and whether it lifts the 7-day rule is undocumented ([browser-storage.com](https://www.browser-storage.com/browser-storage-fundamentals-quotas/storage-quotas-eviction-policies/ios-safari-7-day-storage-eviction-workaround/), [GitHub issue summarising MDN 2026](https://github.com/Martin-2403/ration/issues/8), [qnotepad 2026](https://qnotepad.com/blog/indexeddb-storage-limits-safari-firefox-chrome)). These are secondary sources; WebKit's own storage-policy post was not fetched.
- **PWA and offline**: Godot's PWA option lets a project load offline once loaded before; browsers may still evict caches, so bookmarking or adding to Home Screen is advised ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)).
- **Audio on iPhone**: Safari puts Web Audio in the "ambient" category that the silent switch mutes (WebKit bug 237322); setting `navigator.audioSession.type = 'playback'` on a user gesture is the usual fix (Safari 16.4 or 17+ depending on source), with a looping silent audio element as fallback on older iOS; one report says it did not work on iOS 18.7; "playback" pauses other apps' music ([huddee](https://huddee.com/blog/apple-quietly-fixed-web-audio-bug), [example PR](https://github.com/nulltask/be-music/pull/285), [issue](https://github.com/kreciol/simulator/issues/94)). Browsers block audio until the player interacts ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)); Unity notes iOS audio fails on non-HTTPS ([makaka](https://makaka.org/unity-tutorials/webgl-and-unity)).
- **Asset and load budgets**: GPU memory on mobile WebGL is far tighter, so KTX2/Basis texture compression matters ([PkgPulse](https://www.pkgpulse.com/guides/threejs-vs-react-three-fiber-vs-babylonjs-3d-webgl-2026)); CrazyGames caps initial web game load at 50 MB ([playfox](https://playfox.org/news/html5-engine-2026/)); a 2026 Godot guide targets under 150 MB runtime memory and testing on iPhone Safari first (secondary) ([best-games.io](https://best-games.io/blog/godot-web-export-optimization-guide)).
- Fullscreen and pointer capture must start from an input event handler; tabs pause in the background ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html)).

### Inferences
- Suggested repo layout (single Vite app, simplest for an agent): `index.html` (hub) plus `stories/<slug>/index.html` per story, `src/shared/` for save, audio-unlock, episode loader, ink runner and menu UI, `stories/<slug>/ink/*.ink` for the creator's text, `public/` or per-story asset folders. A pnpm workspace monorepo is only worth it if a story needs a different toolchain (for example a Godot export copied in as static files).
- Saves: keep a small JSON per story (`{ episode, inkState, flags }`) in localStorage, IndexedDB for anything larger; add a one-tap "copy save code" or file export, and prompt iPhone players to Add to Home Screen, because of the 7-day rule.
- Episodes map naturally to ink knots or separate ink files plus per-episode asset folders loaded on demand, so a phone downloads only the current episode.
- Budget suggestion (inference, not a published rule): hub under about 200 KB; first playable screen of each story under about 2 to 5 MB on a phone connection; per-story engine JS under about 400 KB gzipped (Phaser, Pixi, Three.js all fit; Godot and Unity do not).
- The 1 GB site cap and 100 GB monthly bandwidth leave room for several illustrated stories but not for heavy video or uncompressed 3D; compressed textures (KTX2), Draco or meshopt geometry, Opus/AAC audio and WebP/AVIF images are worth standardising early.
- Deploy with the official Pages Actions flow (build with Vite, upload the `dist` artifact, deploy), which also avoids the 10 builds per hour soft limit.

### Gaps
- vite-plugin-pwa (or Workbox) current version and iOS behaviour were not checked.
- WebKit's primary storage-policy documentation was not fetched; the 7-day rule and Home Screen exemption rest on secondary sources quoting it.
- No primary source found for a hard Safari tab memory limit or canvas memory limit on current iPhones.
- The exact current GitHub Actions for Pages versions (upload-pages-artifact, deploy-pages) and artifact size limits were not checked.

## 4. Testing: Playwright or similar for screenshots, automated playthroughs and visual regression

### Takeaway
Playwright's built-in `toHaveScreenshot()` (pixelmatch against committed baselines, with thresholds, masks and animation disabling) is enough for visual regression; WebGL and canvas pages in headless Chromium need SwiftShader flags opted in explicitly, and pixel tests should pin the browser and flags. Narrative logic (ink) can be tested without a browser at all.

### Cited Findings
- `expect(page).toHaveScreenshot()` compares against a committed baseline with pixelmatch, creates the baseline on first run, writes expected, actual and diff images on failure, retries until two consecutive captures match, supports `animations: 'disabled'`, `threshold`, `maxDiffPixelRatio` and masking ([Playwright docs](https://playwright.dev/docs/test-snapshots), [oneuptime 2026](https://oneuptime.com/blog/post/2026-01-27-playwright-visual-testing/view)).
- Chromium's automatic SwiftShader WebGL fallback is deprecated; opting in uses `--enable-unsafe-swiftshader` ([Chromium docs](https://chromium.googlesource.com/chromium/src/+/main/docs/gpu/swiftshader.md)). A Playwright write-up uses `--use-gl=angle --use-angle=swiftshader --enable-unsafe-swiftshader --ignore-gpu-blocklist` ([RenderScreenshot](https://renderscreenshot.com/glossary/webgl-headless), [Barth Cave](https://barthpaleologue.github.io/Blog/posts/webgl-webgpu-playwright-setup/)). Playwright moved the flag into shared Chromium switches so WebGL is not blocklisted on GPU-less machines ([Playwright PR #43615](https://github.com/microsoft/playwright/pull/43615)); sources disagree on whether it is a default arg in every version.
- Dropping `--use-angle=swiftshader` shifted WebGL output enough to fail a snapshot at 97.88% in luma.gl; WebGPU canvas tests worked under xvfb with `--enable-unsafe-webgpu --enable-gpu --use-vulkan=swiftshader` ([luma.gl issue #2874](https://github.com/visgl/luma.gl/issues/2874)).
- Headless can render fonts slightly differently on Linux, so pin OS and browser in CI ([bug0 guide](https://bug0.com/knowledge-base/playwright-visual-regression-testing)).

### Inferences
- A practical test pyramid: (1) Node unit tests that compile every `.ink` file and walk all choices to catch dead ends and missing variables; (2) Playwright scripted playthroughs per story and episode at a 390 px phone viewport, driven by test hooks (for example `window.__story.choose(1)`) rather than pixel-coordinate taps on a canvas; (3) a few `toHaveScreenshot()` checkpoints per episode with fixed seeds, paused game clocks and a tolerance for canvas scenes; (4) a manual pass on a real iPhone before each release, since Playwright's WebKit is not iOS Safari.
- Local context from the creator's own notes: on his Windows PC, Playwright WebKit does not launch and only `--browser=msedge` works, so Safari-engine checks would need a CI runner (Linux WebKit or macOS) or the real phone.
- DOM-based stories are far easier to test than canvas ones (text is assertable), which is one more reason to keep tap-through and scroll stories in DOM.

### Gaps
- No source compared Playwright WebKit rendering against real iOS Safari for WebGL games.
- No dedicated game-testing framework for Phaser or Three.js with 2026 maintenance was found.

## 5. Notable newer tools from 2025 and 2026, with maturity notes

### Takeaway
The real 2026 shifts are WebGPU everywhere (including iPhone on iOS 26), Vite 8 on Rolldown, Phaser 4 stable, Babylon 9 plus WebGPU-only Babylon Lite, and engines courting AI coding agents (PixiJS agent skills, Phaser's proprietary LLM-first Phaser AE, Godot MCP add-ons). Most AI-native engines are early access or closed; the open, documented libraries remain the safer base.

### Cited Findings
- **Phaser AE**: "a completely separate engine that we built from scratch, specifically for LLMs to use", powers the Phaser Game Agent, 2D and 3D, WebGPU-first with WebGL2 fallback, not open source; Early Access announced 17 Jul 2026; v2 around 23 to 24 Jul, v2.5 on 31 Jul, v2.6 on 4 Aug 2026 ([Phaser 4 vs AE](https://phaser.io/news/2026/07/no-you-didn-t-miss-a-3d-update), [AE v2](https://phaser.io/news/2026/07/phaser-ae-v2-is-now-the-engine-behind-every-new-game), [AE v2.6](https://phaser.io/news/2026/08/phaser-ae-v2-6-the-complete-vector-arcade-engine)). The Phaser 4 download page links an "Engine license" at a Polyform Shield URL while the Phaser GitHub repo states MIT ([Phaser downloads](https://www.phaser.io/download/phaser4), [GitHub](https://github.com/phaserjs/phaser)); the Polyform link most likely concerns Phaser's commercial products, but that is unconfirmed.
- **Babylon Lite**: WebGPU-only, tree-shakable, pixel-identical output goal, launched 17 Jun 2026, v1.37.1 on 27 Oct 2026, API still settling ([forum](https://forum.babylonjs.com/t/introducing-babylon-lite/63648), [GitHub](https://github.com/BabylonJS/Babylon-Lite/releases/tag/npm-lite-v1.37.1), [forum p.6](https://forum.babylonjs.com/t/introducing-babylon-lite/63648?page=6)).
- **PixiJS**: 25 official skills for AI coding agents; experimental Canvas renderer; DOM-to-texture `html-source` ([playfox](https://playfox.org/news/html5-engine-2026/), [PixiJS June 2026](https://pixijs.com/blog/june-2026)).
- **Godot AI tooling**: Godot AI, an MIT add-on connecting Claude Code, Codex and Cursor to a live editor (46 tools, scenes, scripts, UI, tests), released for Godot 4.5 and 4.6 ([Asset Library](https://godotengine.org/asset-library/asset/5050), [GitHub](https://github.com/hi-godot/godot-ai)); an opinion piece names Godot and web stacks (Phaser, Babylon, Three.js) as the most reliable engines for text-based agentic tools in mid-2026 ([Medium](https://chierhu.medium.com/ai-coding-tools-for-video-game-development-a-first-principles-analysis-of-what-actually-works-90dfa10edd13)).- **Three.js r184 to r186**: TSL compile about 3x faster (r184), WebXR on WebGPU (r185), async `dispose()` and MSAA for WebXR (r186) ([GitHub releases](https://github.com/mrdoob/three.js/releases)).
- **R3F v10 alpha**: WebGPU default, `@react-three/fiber/legacy` for WebGL ([issue #4026](https://github.com/pmndrs/react-three-fiber/issues/4026)).
- **Yarn Spinner Playground**: web authoring in development, aims to support standalone web games ([Jan 2026 update](https://yarnspinner.dev/blog/monthly_jan_26/)).
- **Gaussian splatting** arrived in mainstream web engines in 2026 (Babylon 9 formats and shadows; PlayCanvas compute splat renderer) ([Cinevva news](https://app.cinevva.com/news/2026-03-26-babylonjs-9), [PlayCanvas forum](https://forum.playcanvas.com/t/engine-v2-19-0/42321)).

### Inferences
- Phaser AE is interesting but closed and tied to Phaser's own agent; for a public repo coded by Claude Code, open Phaser 4 is the safer pick.
- Gaussian splats could give a "realistic look" story photographic scenery cheaply, but file sizes and phone memory make it an experiment, not a base.
- PixiJS's agent skills and Three.js's huge example corpus both help Claude Code write correct code first time; this is a real, if soft, advantage over niche engines.

### Gaps
- No independent maturity review of Phaser AE, Babylon Lite or the Godot MCP tools was found.
- No dedicated MCP server for Phaser or Three.js turned up in searches; those stacks are driven through ordinary file editing.
- Other 2025 to 2026 entrants (for example Needle Engine, Threlte, GDevelop's AI features, Bevy on web) were not researched in this pass.

## 6. Recommended stack and runner-up

### Takeaway
**Recommended**: one Vite 8 + TypeScript multi-page site on GitHub Pages, ink (inkjs 2.4) for every story's text, and a per-story renderer chosen by look: DOM/CSS for tap-through and scroll, Phaser 4 for pixel walk-around (PixiJS 8 if the story is mostly art layers), Three.js r186 (WebGL2 baseline, WebGPU optional) for 3D or realistic. **Runner-up**: Godot 4.7 web exports per story (single-threaded, Compatibility renderer) behind the same Vite hub, accepting about 9 MB per story and more iPhone risk in exchange for one visual editor for 2D and 3D.

### Cited Findings
- Bundle sizes favour the JS libraries: Phaser 345 KB gz, PixiJS about 200 KB, Three.js about 150 to 200 KB tree-shaken, versus Godot about 9 MB gz and Unity about 8 MB ([GitHub Phaser](https://github.com/phaserjs/phaser), [Cinevva](https://app.cinevva.com/guides/web-game-engines-comparison), [PkgPulse](https://www.pkgpulse.com/guides/threejs-vs-react-three-fiber-vs-babylonjs-3d-webgl-2026)).
- WebGPU on iPhone needs iOS 26 ([WebKit](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/)), so a WebGL2 path is still required; Phaser 4 is WebGL ([playfox](https://playfox.org/news/html5-engine-2026/)); PixiJS recommends WebGL for production ([playfox](https://playfox.org/news/html5-engine-2026/)).
- inkjs is MIT, typed, with runtime and compiler split and a CLI ([GitHub](https://github.com/y-lohse/inkjs)).
- Vite MPA with `base` handles the hub-plus-stories structure on a Pages subpath ([Vite docs](https://vite.dev/guide/build)); Pages limits are 1 GB site and 100 GB per month soft bandwidth ([GitHub docs](https://docs.github.com/en/pages/getting-started-with-github-pages/github-pages-limits)).
- Godot web: WebGL2 only, single-thread default, no C#, Safari WebGL2 issues, 2026 iOS audio crash report ([Godot docs](https://docs.godotengine.org/en/latest/tutorials/export/exporting_for_web.html), [issue #116750](https://github.com/godotengine/godot/issues/116750)).

### Inferences
- **Why this stack**: everything is text (TypeScript, `.ink`, JSON), well documented, free (MIT for Phaser, PixiJS, inkjs; Vite and Three.js open source), testable headless with Playwright plus Node, and light enough for iPhone Safari. Each story picks the cheapest tool for its look, and the hub never pays for an engine a story does not use. Cost: zero (GitHub Pages and Actions free for a public repo).
- **Shared core to build once**: save slots with export code, the iOS audio unlock (`navigator.audioSession` plus gesture), an ink runner that maps tags to renderer commands, an episode loader with lazy asset folders, and a Playwright harness with test hooks.
- **When to pick the runner-up**: if the creator wants to lay out walk-around scenes visually himself in an editor, or one story needs real 3D level building, Godot is the best free tool; keep it to that one story, use a custom slimmed export template, test early on a real iPhone, and do the dialogue with Dialogic 2 (alpha) or plain GDScript because C# is not available on web.
- **Component-level alternates**: PixiJS 8 instead of Phaser 4 for art-led 2D; Babylon.js 9 instead of Three.js for a more batteries-included 3D story; Twine/SugarCube only for quick text-only prototypes. Avoid for this project: Unity 6 web (weight, iOS memory, licence tiers), Ren'Py web and ChoiceScript (own whole page; ChoiceScript non-commercial licence), Yarn Spinner (no JS runtime), Kaplay 4000 (alpha), WebGPU-only engines such as Babylon Lite (excludes iPhones before iOS 26).

### Gaps
- No real-device iPhone frame-rate comparison between the recommended renderers exists in the sources; a quick spike (one Phaser scene, one Three.js scene, one DOM story) on the creator's own iPhone is the honest way to close this.
- iPhone share by iOS version (how many players would have WebGPU) was not researched.
